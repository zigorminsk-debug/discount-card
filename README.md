# Мои карты — дисконтные карты в телефоне

[![Build & Release APK](https://github.com/zigorminsk-debug/discount-card/actions/workflows/android-release.yml/badge.svg)](https://github.com/zigorminsk-debug/discount-card/actions/workflows/android-release.yml)
[![Smoke tests](https://github.com/zigorminsk-debug/discount-card/actions/workflows/smoke-test.yml/badge.svg)](https://github.com/zigorminsk-debug/discount-card/actions/workflows/smoke-test.yml)
[![Signing self-test](https://github.com/zigorminsk-debug/discount-card/actions/workflows/signing-selftest.yml/badge.svg)](https://github.com/zigorminsk-debug/discount-card/actions/workflows/signing-selftest.yml)

Android-приложение: сканирует штрих-код или QR-код дисконтной карты, определяет магазин,
создаёт виртуальную карту для предъявления на кассе и показывает на экране ровно ту же
информацию, что была считана. Если магазин не распознан — предлагает сфотографировать
лицевую сторону карты. Дополнительно умеет читать NFC-метки.

Всё работает **полностью офлайн**: ни коды, ни фотографии никуда не отправляются.

## Скачать и установить

**[→ Последний релиз (APK)](https://github.com/zigorminsk-debug/discount-card/releases/latest)**

1. Откройте ссылку с телефона и скачайте файл `MoiKarty-v1.0.*.apk`.
2. Android спросит разрешение на установку из этого источника — разрешите.
3. При первом сканировании приложение попросит доступ к камере, при чтении метки — включить NFC.

Требуется Android 7.0 или новее. Интернет не нужен ни при установке, ни при работе.

| | |
|---|---|
| Язык / UI | Kotlin, Jetpack Compose (Material 3, тёмная тема, динамические цвета Android 12+) |
| Минимальная версия | Android 7.0 (API 24), целевая — Android 15 (API 35) |
| Сканирование | CameraX + ML Kit Barcode Scanning (модель внутри APK, без Google Play Services) |
| Скан без камеры | распознавание кода на скриншоте или фото из галереи |
| Отрисовка кода | ZXing — код рисуется тем же форматом, каким был считан |
| Хранение | Room (SQLite) + файлы фото во внутренней памяти приложения |
| NFC | штатный `NfcAdapter` в режиме Reader Mode (UID, список технологий, NDEF) |
| Сборка | GitHub Actions, подпись постоянным ключом, релиз с номером на каждую сборку |

## Как это работает

### 1. Сканирование

Камера непрерывно ищет код в кадре. Поддерживаются EAN-13, EAN-8, UPC-A, UPC-E,
Code 128, Code 39, Code 93, ITF, Codabar, QR, Data Matrix, Aztec, PDF417.
При распознавании — короткая вибрация и переход к карточке.

### 2. Код со скриншота

Если карта пришла картинкой — скриншотом из мессенджера, фотографией в галерее —
камера не нужна: **⋮ → «Скан со скриншота»** (или кнопка на экране сканера).
Приложение открывает системный выбор фото (разрешения не требуются), ищет на картинке
штрих-код или QR сразу в четырёх ориентациях и дальше ведёт себя как после обычного
сканирования. Кода на картинке нет — её можно сохранить как фото карты.

### 3. Поиск магазина

Универсального реестра дисконтных карт не существует: сети печатают на картах
внутренние коды (обычно серия EAN `20…29`), и одинаковый номер у разных сетей —
обычное дело. Поэтому магазин ищется в четыре шага:

1. **Память приложения.** Если вы уже сохраняли карту с таким же префиксом кода —
   название подставится автоматически (это и есть самый точный способ).
2. **Ссылка внутри QR-кода.** `https://5ka.ru/…`, `vkusvill.ru`, `evroopt.by` и т. д. —
   домен сопоставляется с каталогом из 70+ сетей Беларуси, России и международных.
3. **Ключевые слова** в текстовом содержимом кода.
4. **Правила префиксов** из `app/src/main/assets/stores.json` (если вы их добавите).

Если ничего не нашлось — приложение честно пишет «Магазин не распознан» и предлагает
**сфотографировать лицевую сторону карты**: фото сохраняется рядом с кодом и его
всегда можно показать кассиру. Название вводится вручную — и запоминается:
следующая карта той же сети распознается сама.

### 4. Карта на кассе

На экране карты: штрих-код в исходном формате на белой подложке (яркость экрана
автоматически поднимается до максимума, экран не гаснет), крупный номер моноширинным
шрифтом (нажатие — копирование), название формата, фотографии карты.

### 5. NFC

Экран «NFC-карта» включает Reader Mode и читает UID метки, список технологий
(NfcA/NfcB/NfcF/NfcV, MIFARE, ISO-DEP) и содержимое NDEF (текст и ссылки).
Прочитанное сохраняется как карта; если в NDEF была ссылка или номер — он
используется как код карты и рисуется штрих-кодом.

> **Честно о возможностях NFC.** Android не позволяет клонировать и эмулировать чужие
> бесконтактные карты: UID защищён на аппаратном уровне, а HCE работает только с
> собственными апплетами эмитента. Поэтому приложение **читает и хранит** данные метки,
> но не притворяется ею у терминала. На кассе показывайте номер, штрих-код или
> саму пластиковую карту. Любое приложение, обещающее иное, вводит в заблуждение.

### 6. Перенос карт на другой телефон

Меню «⋮» → **«Отправить карты»**: все карты вместе с фотографиями пакуются в один
файл `moi-karty-<дата>.mkcards` (внутри обычный zip с `cards.json`) и уходят в системное
«Поделиться» — Telegram, почта, Bluetooth, что угодно.

На втором телефоне достаточно **нажать на файл прямо в Telegram** — приложение
перехватывает такие файлы и открывает экран переноса; либо меню «⋮» → «Получить карты»
и выбрать файл вручную. Перед добавлением показывается, сколько карт в файле и когда он
сделан. Карты, которые уже есть (тот же код или та же NFC-метка), пропускаются, поэтому
повторный импорт ничего не задваивает. Вместе с картой переезжает и выученное
соответствие «код → магазин».

Файл не шифруется — это ваши же номера карт в открытом виде, так что не выкладывайте
его в публичные чаты.

## Каталог магазинов

Файл `app/src/main/assets/stores.json` — обычный JSON, его легко расширить:

```json
{
  "id": "evroopt",
  "name": "Евроопт",
  "country": "BY",
  "color": "#E4002B",
  "aliases": ["Евроопт", "Е-доставка"],
  "domains": ["evroopt.by", "e-dostavka.by"],
  "keywords": ["evroopt", "евроопт"],
  "rules": [
    { "prefix": "2612", "lengths": [13], "formats": ["EAN_13"], "confidence": "high" }
  ]
}
```

* `domains` / `keywords` — ищутся в тексте QR-кода;
* `rules` — срабатывают для числовых штрих-кодов: `prefix`, `regex`, `lengths`, `formats`;
* `confidence`: `high` — «магазин распознан», иначе «похоже на магазин».

В разделе `issuers` лежат префиксы GS1 (460–469 — Россия, 481 — Беларусь, 20–29 —
внутренний код магазина): приложение подсказывает, кем выпущен код, даже когда
конкретная сеть неизвестна.

## Сборка

### В GitHub Actions (основной путь)

Workflow `.github/workflows/android-release.yml` запускается:

* при push в `main` / `master` / `arena/**`;
* вручную — **Actions → Build & Release APK → Run workflow** (можно задать базовую версию);
* на pull request — только сборка, без публикации релиза.

Каждая сборка:

1. получает свой номер — `github.run_number`;
2. собирается как `versionName = <appVersionBase>.<номер>`, `versionCode = <номер>`
   (базовая версия задаётся в `gradle.properties`, по умолчанию `1.0`);
3. подписывается постоянным ключом из секретов;
4. публикуется GitHub Release с тегом `v1.0.<номер>`, APK, SHA-256 и отпечатком ключа.

Релизы из веток, кроме `main`/`master`, помечаются как pre-release.

### Локально

```bash
./gradlew assembleRelease     # подпись возьмётся из keystore.properties
./gradlew assembleDebug       # отдельный applicationId .debug, ставится рядом
```

Нужны JDK 17 и Android SDK 35.

## Подпись и обновления

Обновление ставится поверх установленного только при совпадении ключа подписи,
поэтому ключ один на всю жизнь приложения. Что это действительно работает, проверяет
отдельный workflow `upgrade-test.yml`: он ставит на эмулятор опубликованный релиз и
накатывает поверх новую сборку. Подробности, резервное копирование и
восстановление — в [`keystore/README.md`](keystore/README.md).

Коротко: ключ `keystore/release.p12` создан, в git не попадает, а в CI приходит из
секретов `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
Залить их в репозиторий можно одной командой:

```bash
./tools/setup-signing-secrets.sh
```

**Пока секретов нет**, сборка подписывается запасным ключом `keystore/ci-fallback.p12`,
который лежит прямо в репозитории. Он не секретный — зато **одинаковый во всех сборках**,
поэтому новая версия спокойно встаёт поверх установленной. Такие релизы помечаются
pre-release, в заголовке стоит «— открытый ключ», в имени файла — суффикс `-CIKEY`,
отпечаток: `00:92:37:8F:4F:75:8A:F3:82:B8:E9:8A:93:53:A1:B8:BD:1D:69:FF:86:63:54:55:71:47:45:C0:19:D2:7B:DB`.

> Переход на личный ключ (отпечаток `6B:73:CC:CA:…:30:7F`) меняет подпись, поэтому
> приложение придётся один раз удалить и поставить заново — карты из базы при этом
> пропадут. Если собираетесь это делать, лучше сразу, пока карт немного.

## Проверки в CI

Кроме сборки репозиторий гоняет три отдельных workflow:

| Workflow | Что проверяет |
|---|---|
| `signing-selftest.yml` | генерирует временный ключ, собирает релиз и убеждается, что `apksigner` видит подпись v2+v3, а `versionCode` / `versionName` / `minSdk 24` / `targetSdk 35` / `assets/stores.json` / список разрешений в собранном APK — именно те, что заявлены |
| `upgrade-test.yml` | берёт **последний опубликованный релиз**, ставит его на эмулятор, сверху накатывает свежую сборку (`adb install -r`) и проверяет: отпечатки ключей совпадают, `firstInstallTime` не изменился (значит это обновление, а не переустановка), данные приложения на месте, приложение запускается |
| `smoke-test.yml` | запускает APK на эмуляторе Android 14 **с системным шрифтом 1.3**: приложение стартует без падения, кнопки не уезжают под панель навигации, каталог магазинов читается, EAN-13 рисуется как EAN-13 (а произвольная строка — как Code 128), Room сохраняет карту и запоминает префикс сети, экспорт-импорт восстанавливает карты и фото. Снимки экранов выкладываются в ветку `ci-logs` |

Если сборка падает, полный лог Gradle и XML-отчёты тестов выкладываются в служебную
ветку `ci-logs` — туда же, где их можно прочитать без скачивания артефактов.

## Приватность

Разрешения в собранном APK (проверяется автоматически на каждом прогоне
`signing-selftest.yml`):

```
android.permission.CAMERA    сканирование кода и съёмка карты
android.permission.NFC       чтение меток
android.permission.VIBRATE   отклик при распознавании кода
```

Картинки из галереи берутся через системный выбор фото — доступ ко всей галерее
приложению не нужен и не запрашивается. Разрешения `INTERNET` и `ACCESS_NETWORK_STATE`, которые по умолчанию подмешивают
библиотеки ML Kit, принудительно удалены из манифеста — приложение физически не может
выйти в сеть. База и фотографии лежат во внутреннем хранилище приложения и удаляются
вместе с ним.
